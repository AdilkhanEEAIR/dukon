Как работаем: ты пишешь «заход N» — я делаю весь заход целиком, прогоняю тесты/линтер/сборку, снимаю скриншоты на телефоне/планшете/ПК, отдаю zip + команды + что проверить. Если недоволен — пишешь что именно, я правлю в этом же заходе. Пишешь «ок, заход N+1» — идём дальше. Каждый заход самодостаточен: в нём есть весь контекст, чтобы начать даже в новом чате.

## 1. Новая дизайн-система «Ledger» (решение, которое проверяем в заходе 1)

Почему прошлое выглядело «как ИИ»: тёмно-синий фон + электрик-синяя кнопка + карточка-в-карточке + три насыщенных статусных цвета рядом — это дефолт любого генератора. Делаем противоположное: **бумага, чернила, один акцент, крупные цифры, тонкие линии.**

**Направление A — «Ledger» (рекомендую).** Светлая тема по умолчанию, тёмная — по системе.
- Фон `#F6F4EF` (тёплая бумага), поверхность `#FFFFFF`, чернила `#15130F`, вторичный `#6B665C`, линии `#E6E2D9`.
- Один акцент — кобальт `#1F4BD8` (кнопка, ссылки, активный таб). Никаких фиолетовых чипов.
- Статусы — не заливки, а **тон + маленькая метка**: «нет» `#B4231F` (кирпич), «мало» `#8A5A00` (охра, не жёлтый), «ценник» `#1F4BD8`, «ок» `#2F6B3A`. Используются только в тексте и 3-пиксельной метке слева, фон остаётся бумажным.
- Шрифты: заголовки и большие числа — `Instrument Serif` (редакционный контраст), интерфейс — `Inter` с `font-feature-settings: "ss01","tnum"`, цифры в таблицах — `tabular-nums`. Моно — `Geist Mono` только для кодов/сумм в логе агента.
- Сетка: не карточки, а **секции, разделённые хайрлайнами**; карточка только там, где нужен объект (товар, заказ). Радиусы 10/14, тени — одна мягкая на всплывающих элементах, нигде больше.
- Тёмная тема: `#111110` фон, `#1A1917` поверхность, бумажно-белый текст `#F2EFE8`, тот же кобальт, статусы чуть светлее. Не navy.

**Направление B — «Graphite»** (если хочешь остаться тёмным): графит `#141414`/`#1C1C1C`, бумажный текст, тот же единственный кобальт, та же типографика. Отличие только в фоне.

Скажи в «заход 1»: «A» или «B». По умолчанию — A.

**Анимация (по Ковальски).** Переходы страниц — `View Transitions API` с кроссфейдом 180 мс; появление списка — стаггер 30 мс, `translateY(6px)+opacity`, ease-out; числа на главной — count-up 600 мс один раз при появлении; кнопка — `scale(0.97)` на `:active`, 120 мс; шторка (детали товара на телефоне) — `motion` с drawer-кривой, свайп вниз закрывает; тост — въезжает снизу, выезжает туда же; скелетон → контент — кроссфейд, без прыжка высоты; таббар — активная иконка без анимации (частое действие). Hover — только на устройствах с hover (`@media (hover: hover)`). Всё отключается при `prefers-reduced-motion`.

**Языки.** Словари `en`, `ru`, `es`, `de`, `fr` в `frontend/src/i18n/*.ts`, типизированный `t('home.loss')`, переключатель в онбординге и в настройках; язык в `localStorage`, по умолчанию — язык браузера, иначе `en`. Валюта — отдельно от языка (сом по умолчанию, `KGS`), форматирование через `Intl.NumberFormat`. Названия товаров с полок **не переводим** — это данные.

## 2. Два режима работы (стандарт и запасной)

| | Стандарт (live) | Запасной (demo) |
|---|---|---|
| Когда | `PROVIDER=meta`, ключ есть, бюджет не исчерпан, демо-код введён | нет ключа / нет кредитов / ошибка моделей / лимит / пользователь сам выбрал «демо» |
| Что делает | SAM 3.1 + Muse Spark на реальных фото | детерминированные данные из `data/demo` (настоящие фото + заранее размеченные ответы) |
| Как показываем | пилюля «Live · осталось N вызовов» | пилюля «Демо · причина» (например «нет кредитов на аккаунте») |

Логика: `GET /health` отдаёт `mode: "live"|"demo"`, `reason`, `budget: {calls_today, calls_limit, est_spend_usd, last_error}`. Фронт держит `ModeContext`. `POST /walks/analyze?mode=auto` на бэкенде: пробует live, при `ProviderError` с кодом `auth|billing|rate_limit|network` — **сам переключается** на демо-провайдер и помечает обход `source: "fallback"`, `fallback_reason`. UI показывает жёлтую строку «Показали демо-результат: <причина>. Повторить вживую». Баланс считается автоматически: каждая удачная пара вызовов SAM+Spark увеличивает счётчик и оценку расхода (константы в `config.py`, обновим, когда увидим реальные цены в Billing). Ошибки моделей пишутся в `storage.counters` и показываются на странице «Система» (маленькая, но судьям полезна: видно, что мы считаем деньги).

Первый экран — **не демо-обход, а продукт**: `/` — лендинг (заголовок, как работает, кнопки «Открыть приложение» и «Посмотреть демо», выбор языка), `/app` — после онбординга (название магазина, язык, валюта — 3 поля, 10 секунд). Демо-обход появляется только если нажали «Посмотреть демо» или live недоступен.

### Заход 4 — Агент: правила, переговоры с поставщиком, журнал решений
**Цель:** главное для Best Agentic и Technical depth. «Модель предлагает — код проверяет».

**Контекст:** правила хозяина — `data/rules.json` (макс. сумма заказа в день, запрещённые поставщики, не заказывать молочку на пятницу, не больше 2 недель запаса, минимальная скидка для увеличения объёма). **Делаем:** `agent/loop.py` (макс. 8 шагов, таймаут, бюджет на вызовы), `GET /agent/runs/{id}/events` (SSE), `POST /agent/run?walk_id=`; события: `thought`, `tool_call`, `verifier_block` (с правилом), `supplier_reply`, `final`. Фронт `/app/agent`: лента событий, появляющихся по одному (стаггер, ease-out), момент **блокировки правилом — визуально выделен** (это главный кадр для видео), итог: что заказано, что отвергнуто и почему. Тесты: verifier на каждое правило, loop с мок-моделью, SSE-парсер на фронте, экран с записанным прогоном.
